# srvbot — Telegram-бот мониторинга сервера

Небольшой бот для своего Linux-сервера. Он присылает алерты, показывает состояние сервера кнопками и позволяет управлять сервером из Telegram. Отвечает только владельцу. Памяти занимает около 20 МБ. Из зависимостей — только Python и `psutil`.

## Что умеет

**Разделы (кнопки внизу чата)**

| Кнопка | Что показывает |
|---|---|
| 📊 Сервер | Аптайм и нагрузка, CPU, RAM, диск, IP, службы, контейнеры, порты, сертификаты; одной строкой баны fail2ban и доступные обновления. Отсюда кнопки 🔧 Службы и журналы (перезапуск, журналы) и 🛡 Баны (кто забанен, «Разбанить»; есть и команда `/bans`) |
| 🔐 Клиенты | Клиенты туннеля в docker-контейнере: кто в сети, внутренний IP, трафик, страна и провайдер. У каждого клиента свой эмодзи. Кнопка появляется сама, если туннель найден |
| 🌍 Доступность | Карточка риска блокировки адреса (возраст IP, проверки из выбранной страны за сутки, трафик за сегодня) и проверка сервера с ~60 узлов check-host.net по всему миру |
| 📋 Отчёт | За неделю: трафик по клиентам и баны |
| ⚙️ Управление | Установка обновлений, очистка диска, перезагрузка. Всё только после подтверждения |

В чате остаётся одна последняя сводка: предыдущая удаляется сама.

**Алерты** (🔴 при проблеме, 🟢 когда починилось, без повторов):
- контейнер с автоперезапуском остановился или исчез;
- служба systemd упала;
- диск заполнен на 90% и больше;
- CPU или память под нагрузкой 5 минут подряд;
- пропал слушающий порт (если контейнер пересоздали с другим портом, старый забывается сам, без алерта);
- служба слушает IP, которого больше нет на сервере;
- сменился внешний IP сервера;
- сервер недоступен хотя бы с одного узла check-host.net в выбранной стране (ни TCP к порту SSH, ни ping), а с контрольных узлов доступен; если недоступен лишь с части узлов, так и сказано — похоже на блокировку у отдельных провайдеров;
- данные клиентов туннеля не читаются;
- клиент шлёт пакеты, но рукопожатие не проходит 3 проверки подряд — похоже, сеть режет начало соединения;
- все клиенты (от двух) пропали из сети одновременно — похоже на блокировку адреса сервера; бот тут же внепланово проверяет доступность из страны;
- трафик клиентов за сегодня превысил порог (раз в день, без 🟢): объём трафика повышает риск блокировки;
- сертификат Let's Encrypt истекает меньше чем через 14 дней;
- появился новый клиент;
- вход по SSH;
- бан в fail2ban, если подключён action (см. ниже).

Под алертами есть кнопки действий, и действие открывается отдельным сообщением с подтверждением, а сам алерт остаётся. Когда проблема уходит, 🟢 приходит ответом на свой 🔴 с длительностью простоя, а кнопки с 🔴 исчезают.

| Алерт | Кнопки |
|---|---|
| контейнер не работает, данные туннеля не читаются | 🔄 Перезапустить · 📜 Журнал |
| служба упала | 🔄 Перезапустить · 📜 Журнал |
| docker не отвечает | 🔄 Перезапустить docker · 📜 Журнал |
| диск заполнен | 🧹 Очистить диск |
| CPU или память | 📊 Сервер · 🔧 Службы |
| контейнер исчез, порт пропал | Забыть · 🔧 Службы |
| недоступен из страны | 🌍 Проверить по миру |
| рукопожатие не проходит, все клиенты пропали, трафик выше порога | 🌍 Доступность · 🔐 Клиенты |
| обновления установлены, нужна перезагрузка | ⏻ Перезагрузить |

**По расписанию** (в часовом поясе из настроек): по понедельникам в 10:00 — недельный отчёт.

**При запуске** бот пишет, как он стартовал: штатно, после своего сбоя или после перезагрузки сервера — тогда с длительностью простоя. Если docker не отвечает (например, сервер перегружен), 📊 Сервер и 🔐 Клиенты не виснут, а показывают последние известные данные с пометкой, когда они получены.

## Требования

- Ubuntu 22.04/24.04 или Debian 12, доступ root.
- Python 3.10+ (уже есть в системе). `python3-psutil` установщик поставит сам.
- Docker и fail2ban — по желанию: чего нет, бот просто не показывает.

## Установка

1. Создайте бота: в Telegram напишите [@BotFather](https://t.me/BotFather) → `/newbot` → сохраните **токен**.
2. Узнайте свой **Telegram ID**: напишите [@userinfobot](https://t.me/userinfobot), он ответит числом.
3. На сервере выполните:

```bash
git clone https://github.com/avcolgate/srvbot.git /opt/srvbot
cd /opt/srvbot
sudo ./install.sh
```

Установщик задаст три вопроса и запишет ответы в `/etc/srvbot.env`:

| Вопрос | Обязательно | Если пропустить (Enter) |
|---|---|---|
| токен бота (`BOT_TOKEN`) | да | — |
| ваш Telegram ID (`OWNER_ID`) | да | — |
| страна для проверки доступности (`CHECK_COUNTRY`), например `de` | нет | проверки нет |

Остальное бот определяет сам: часовой пояс берёт у сервера, а контейнер туннеля и список клиентов находит автоматически (см. ниже).

Затем он проверит токен в Telegram, поставит службу и запустит её. Бот пришлёт «🤖 бот мониторинга запущен» — нажмите `/start`, чтобы появились кнопки. При повторном запуске (например, при обновлении) установщик спрашивает только то, чего ещё нет в `/etc/srvbot.env`.

Бот отвечает только вам и только в личном чате. Чтобы его нельзя было добавить в группу, у [@BotFather](https://t.me/BotFather) выполните `/setjoingroups` → выберите бота → **Disable**.

Без вопросов, например из скрипта, — переменными окружения:

```bash
sudo BOT_TOKEN=123:ABC OWNER_ID=123456789 CHECK_COUNTRY=de ./install.sh
```

Не нужны уведомления о входе по SSH — `sudo ./install.sh --no-ssh-alerts`. Тогда установщик не будет трогать `/etc/pam.d/sshd`.

## Настройки сервера: `/etc/srvbot.env`

Всё, что относится к конкретному серверу, хранится в `/etc/srvbot.env` (права 600). В репозиторий этот файл не попадает. Обычно в нём всего три строки:

```ini
BOT_TOKEN=1234567890:AAAA-ваш-токен
OWNER_ID=123456789
CHECK_COUNTRY=de
```

**Как бот находит туннель.** Он проходит по запущенным docker-контейнерам и смотрит их сетевые интерфейсы. Утилита туннеля обычно называется так же, как интерфейс без номера (`xyz0` → `xyz`). Если такая утилита есть в контейнере и отвечает на `show all dump`, контейнер считается туннелем, и в Telegram появляется кнопка «🔐 Клиенты». Имена клиентов бот берёт из JSON-файла внутри контейнера, в котором встречается ключ клиента. Если туннеля нет, кнопки нет.

### Тонкая настройка

Обычно не нужна. Добавьте строку в `/etc/srvbot.env` и выполните `sudo systemctl restart srvbot`. Все ключи есть в [`srvbot.env.example`](srvbot.env.example).

| Ключ | Когда нужен | Пример |
|---|---|---|
| `TIMEZONE` | отчёт и время в сообщениях нужны не по часовому поясу сервера | `Europe/Paris` |
| `TUNNEL_MATCH` | автоопределение не нашло контейнер — подстрока имени или образа | `my-tunnel` |
| `TUNNEL_TOOLS` | утилита называется не как интерфейс | `tunctl` |
| `TUNNEL_CLIENTS` | список клиентов лежит там, где бот не ищет (ищет в `/opt`, `/etc`, `/var/lib`, `/root`) | `/etc/tunnel/clients.json` |
| `PORT_PROCESSES` | контролировать порты ещё каких-то процессов (sshd, nginx, docker-proxy — всегда) | `caddy,postgres` |

Самый простой формат списка клиентов — ключ клиента и имя:

```json
[
  {"publicKey": "kE9x…=", "name": "laptop"},
  {"publicKey": "Qm2a…=", "name": "phone"}
]
```

Подойдёт и словарь `{"<ключ>": {"name": "laptop"}, …}`. Если файла нет, вместо имён показывается начало ключа.


## Пороги алертов

Пороги и расписание — в [`srvbot/config.py`](srvbot/config.py). После правки выполните `sudo systemctl restart srvbot`.

| Параметр | По умолчанию | Что значит |
|---|---|---|
| `DISK_PCT` | 90 | алерт, если диск заполнен на N% |
| `CPU_PCT`, `SUSTAIN_CHECKS` | 90, 5 | CPU ≥ N% столько минут подряд |
| `MEM_AVAIL_PCT` | 8 | свободно меньше N% RAM |
| `GEO_CHECK_INTERVAL`, `GEO_SUSTAIN` | 600, 2 | проверка страны раз в 10 мин, алерт после 2 неудач подряд |
| `TUNNEL_ONLINE_SEC` | 180 | рукопожатие свежее N секунд — клиент в сети |
| `TUNNEL_STALL_CHECKS` | 3 | пакеты от клиента приходят без рукопожатия N проверок подряд — алерт |
| `TRAFFIC_DAY_GB` | 20 | предупреждение, если клиенты за сегодня прокачали больше N ГБ |
| `REPORT_HOUR`, `WEEKLY_WEEKDAY` | 10, пн | когда приходит недельный отчёт |
| `CMD_TIMEOUT`, `UI_CMD_TIMEOUT` | 30, 10 | сколько ждать docker и прочие команды: в фоновых проверках и в ответах на команды из чата |

### Уведомления о банах fail2ban

Установщик кладёт action `/etc/fail2ban/action.d/srvbot.conf`. Чтобы получать сообщение о каждом бане с кнопкой «Разбанить», добавьте его в нужный jail в `/etc/fail2ban/jail.local`:

```ini
[nginx-limit-req]
action = %(action_)s
         srvbot
```

Затем выполните `sudo fail2ban-client reload`. Для `sshd` подключать не советую: банов там десятки в день. Они и так видны в разделе 🛡 Баны (кнопка в 📊 Сервер или команда `/bans`) и в недельном отчёте.

**Ubuntu 24.04:** стандартный jail `sshd` там ничего не ловит, потому что служба SSH называется `ssh.service`, а не `sshd.service`. Чтобы заработал, допишите в `jail.local`:

```ini
[sshd]
enabled = true
journalmatch = _SYSTEMD_UNIT=ssh.service + _COMM=sshd
mode = aggressive
```

## Удаление

```bash
sudo /opt/srvbot/install.sh --uninstall
```

Удаляются служба, скрипты и хук SSH. `/etc/srvbot.env` и `/var/lib/srvbot` остаются — удалите их вручную, если не нужны.

## Безопасность и внешние сервисы

- Бот работает от root (ему нужны docker, fail2ban, apt, перезагрузка) и выполняет команды только от `OWNER_ID` и только в личном чате. Произвольные shell-команды он не выполняет — только заранее заданные действия, каждое с подтверждением.
- Берегите токен бота и свой аккаунт Telegram: у кого они, у того управление сервером.
- **check-host.net** проверяет доступность сервера. Ему передаётся только IP сервера.
- **ipinfo.io** определяет страну и провайдера клиентов. Ему передаются внешние IP клиентов при открытии раздела клиентов, ответ кэшируется на сутки.

## Как устроено

```
srvbot/
  __main__.py   запуск: Telegram long polling + фоновые проверки
  tg.py         свой минимальный клиент Bot API (только IPv4, см. ниже)
  handlers.py   кнопки, команды, подтверждения
  views.py      тексты разделов
  alerts.py     фоновые проверки и расписание
  tunnel.py     клиенты туннеля: поиск контейнеров, разбор `show all dump`, эмодзи клиентов
  checkhost.py  проверки через check-host.net
  manage.py     обновления, службы и журналы, очистка диска
  system.py, docker.py, report.py, geoip.py, notify.py, config.py, util.py
deploy/         шаблоны systemd-юнитов, PAM-хука и action для fail2ban
tests/          python3 -m unittest
```

Почему так:
- **Без aiogram и прочих библиотек.** Рассчитано на сервер с 1 ГБ RAM, а одна загрузка aiogram занимает ~160 МБ. Свой клиент на стандартной библиотеке Python занимает ~20 МБ.
- **Только IPv4 до Telegram.** С некоторых хостингов IPv6 до `api.telegram.org` иногда зависает, и бот «замирал» на 30–60 с.
- **Обновления в отдельной службе** (`srvbot-upgrade`). Если apt по ходу перезапустит бота, установка всё равно не прервётся.

Тесты:

```bash
cd /opt/srvbot && python3 -m unittest -v
```
